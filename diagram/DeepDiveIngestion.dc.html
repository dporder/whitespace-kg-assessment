What arrives
Native text PDF
Every glyph already carries its position, boxes are read, not inferred. RM6116 is this case.
Scans and photos
No text layer. The ladder takes over, and the page image itself is kept and linked so a reader can always see the scan beside the text.
Forms
Label and value rows, placeholders preserved verbatim.
Here. The Award Form, "[Insert name]" cells and a real stray-character typo, "rFramework", recorded, never repaired.
Figures and illustrations
Captioned regions with boxes. A model may describe them for search, and the description is flagged derived, never citable. The kinds registry holds figure, caption and legend for families that need them.
Profile, then refuse or proceed
Rulebook
How a family of documents is structured, stored as config. Unit names, numbering grammar, citable kinds, interpretation-clause cues. A new family is a new entry plus a fixture test, never parser edits.
Example. An EU regulation with Articles and Recitals is one new rulebook entry. The assembler never changes.
Five fit checks
1. Interpretation clause found, naming units we know.
2. Observed numbering covered by the grammar.
3. Almost no text left homeless after tree building.
4. Depth within the declared range.
5. Indentation agrees with numbering.
Plainly. If the document says "Article means" and the rulebook has never heard of Articles, wrong rulebook. Stop.
Quarantine
Any alarm stops the document, evidence attached, exit code 2, no load. A person picks the right rulebook. Never parse anyway.
Extraction ladder, cost rises rung by rung
Classify each page, free
Character count, image area, table count, font histogram. Text-rich or scan-like decides the route.
Text layer, deterministic
Read glyphs and boxes directly. The whole 475 pages run this way here, no model cost.
Layout OCR
Scan-like pages render to images, a layout model returns words with boxes.
Vision model, high zoom
Only where cheaper rungs disagree or return thin results. Thin scans re-render tiled with overlap and stitch.
Table safety net
A deterministic table detector cross-checks the model output. A missed table is re-extracted from a high-resolution crop of just that region.
Cross-page table stitch
Tables hugging facing page edges are detected by position and re-read as one table, not two fragments.
Fallback chain, always lands
Every model call sits in a chain that ends at the deterministic parser, including content-filter false positives, so extraction degrades, never throws.
Every page records the route it took, so downstream confidence can be discounted where the ground was weaker.
Parse, then assemble
Parse
Headers and footers stripped by position and repetition, but the printed page is kept, it is what a lawyer quotes. Part boundaries found where the footer signature changes, each part carries its own template version. Columns detected by box geometry, not line order.
Example. The definitions schedule is two columns and terms wrap mid-cell across lines. Line-order parsing shreds it, geometry does not.
Assemble
Numbering becomes the tree. A node holds text or holds children, never both, and a clause's lead-in sentence becomes an intro child so every character has exactly one home.
Example. Clause 9.1 reads "to enable it to both", then (a) and (b). The lead-in is an intro child, citing 9.1 renders all of it together.
Geometric invariants mean the tree is checked against the printed page. A child's box sits inside its parent's, and 3.1.2 must sit further right than 3.1. When numbering says one depth and layout says another, the tree is probably wrong even though the numbers parsed.
Anomalies stay anomalies. The brief says 35 Core Terms clauses, a plain heading pattern finds 34, so one heading is deliberately hunted and its difference recorded. Nothing is silently repaired.
What comes out
One Node schema, addressable ink

id, this version's instance
lineage_key, across versions
own + extent boxes, per page
printed_page "11"
unit_label "Clause"
anomalies []
Every node knows its page and its box, so anything built on top can prove itself by rendering the page and drawing the rectangle. Identity is the path, never the bare number, because numbering restarts in every part.
Why two boxes. Own covers the node's words, extent covers everything nested under it. A viewer highlights one lettered item or the whole clause without walking the tree.
From here the tree fans out to references, vocabulary, concepts and embeddings, all in parallel, and nothing downstream ever edits what this stage produced.
