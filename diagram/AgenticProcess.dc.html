How this was built
The agentic process behind this assignment, and the standing practice behind the process.
Dan Porder, September 2026
PHASE 1
Interrogate before anything
The model reads everything first, the brief, the document, my notes, then it interviews me, not the reverse. I answer by voice, Wispr Flow dictation, messy is fine, the decisions are what count. A dedicated agent keeps a decisions log so nothing dies with a chat window.
output: shared understanding + a log
PHASE 2
Design is the deliverable
DESIGN, EVALUATION and the build SPEC argued through written feedback rounds, hours of my dictated critique absorbed per round, before any code. Nothing built until sign-off. The spec is then frozen for workers, changed only through the orchestrator with me.
output: contracts worth freezing
PHASE 3
Pre-seed the repo
Agents seed the operating contract (CLAUDE.md), worker role definitions, config, frozen schemas and hand-made fixtures before the build session exists. A fresh orchestrator then boots from one pasted line and inherits everything (KICKOFF.md).
output: a repo agents can inhabit
PHASE 4
A fleet, not a chat
One orchestrator, specialist workers in isolated git worktrees, disjoint file ownership, contracts first. An adversarial reviewer and a tester gate every branch, nobody merges their own work, and what I rejected from agents and why is a kept artifact, REVIEW-NOTES.
output: code that survived scrutiny
PHASE 5
Parallel lanes
While the fleet builds, a second session makes the diagram and slides, background researchers verify claims against primary sources, one wrong claim was caught and corrected on the record, and sweep agents preserve decisions. My attention is the scheduler.
output: wall-clock compressed
PHASE 6
Trust output, not claims
Real command output or it did not happen. Deliverables get second-pass adversarial review, the first pass on this very diagram caught three buried labels. Before anything ships, the docs are reconciled against what actually ran, in the tense it deserves.
output: claims that hold up
Standing practice, the same method every project
Every repo gets an agent entrypoint. A system map, hard rules, and change-X-also-update-Y tables, because regressions come from the second file nobody touched.
Style as executable spec. Canonical voice and convention files with checker scripts agents must run. Conventions that are not executable are suggestions.
Context designed to outlive sessions. Decision logs, handoff notes, indexes of past conversations. Future agents inherit understanding instead of re-deriving it.
Agents draft, humans send. Anything outward-facing is drafted for me and sent by me. Authorship and accountability stay human.
Right-size the ceremony. Full orchestration for fidelity work, a fast path for small changes, and the choice is surfaced, never taken silently. Reflexive process is itself a failure mode.
Eval-first, everywhere. Golden sets, judges aligned to human labels before they run at volume, gates that fail loudly. The same habit this assignment's stage 8 encodes.
